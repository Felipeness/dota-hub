# Decisão técnica: stack das fases 2 e 3

Data: 06/10/2026. Spec: `docs/superpowers/specs/2026-10-06-dota-hub-fase2-3-design.md`. Base: `docs/superpowers/decisions/2026-10-06-stack.md` (fase 1).

## Escolha

| Parte | Escolha |
|---|---|
| Conta | AWS pessoal do Felipe, perfil de CLI `pessoal`. Nunca as contas de trabalho. |
| Região | `us-east-1`, fixada no provider (nunca a região padrão do perfil). |
| Site | S3 privado + CloudFront com Origin Access Control, endereço padrão `*.cloudfront.net`, HTTPS obrigatório, `PriceClass_All`. |
| Rotas do app | CloudFront Function no `viewer-request` reescreve caminho sem extensão para `/index.html` (o react-router cuida da tela); arquivos de dados que faltam continuam 404. |
| Busca ao vivo | API Gateway HTTP API (`ANY /api/{proxy+}`) + Lambda em TypeScript, Node 22 (`nodejs22.x`, arm64, 256 MB, 10 s), atrás do mesmo CloudFront em `/api/*`. |
| Cache e limites | DynamoDB on-demand, uma tabela (`pk` texto), TTL no atributo `ttl`. Guarda os resultados da fonte e os contadores de limite. |
| Infraestrutura como código | Terraform (`hashicorp/aws` 6.x), estado remoto em S3 com `use_lockfile = true`; bucket do estado criado por um módulo `infra/bootstrap` com estado local. |
| Custo | AWS Budgets de US$ 5 filtrado pela etiqueta `projeto=dota-hub`, avisos por SNS e e-mail, e uma Lambda de corte que zera o throttling da API quando o orçamento estoura. |
| Logs | CloudWatch Logs com retenção de 7 dias; logs em JSON sem IP. |
| Publicação | Scripts `bash` no PC do Felipe (`scripts/publicar.sh`, `voltar.sh`, `religar-busca.sh`), sempre com `--profile pessoal`. |
| Código da busca | Pacote `api/` no mesmo repositório: TypeScript strict, zod 3, vitest, esbuild para o bundle, AWS SDK v3 (`@aws-sdk/lib-dynamodb`, `@aws-sdk/client-apigatewayv2`). |

## Por quê

- **AWS na conta pessoal**: já existe, com o perfil `pessoal` configurado, budget geral da conta e a experiência da plataforma médica. Sem conta nova e sem misturar com trabalho. Etiqueta `projeto=dota-hub` em tudo separa o custo deste projeto do resto da conta (lição do projeto Yamaha: conta com duas stacks misturadas não diz o custo de nenhuma).
- **`us-east-1`**: é onde ficam as métricas de cobrança e o Budgets, e é a região exigida pelo certificado do CloudFront quando entrar um domínio próprio. A latência até o Brasil (cerca de 120 ms) cabe no critério de 4 s da busca. A região fica escrita no provider: comando que dependa da região padrão do perfil cria recurso no lugar errado.
- **S3 + CloudFront**: o app da fase 1 é estático. O tráfego esperado cabe no nível gratuito permanente do CloudFront (1 TB e 10 milhões de requisições por mês). `PriceClass_All` porque os usuários estão no Brasil: as classes mais baratas não incluem os pontos da América do Sul e a primeira tela ficaria mais lenta; dentro do nível gratuito a diferença de preço não aparece.
- **API no mesmo CloudFront**: o navegador fala com um endereço só, então não há CORS para configurar e nenhum endereço de API aparece no código do site. A API continua pública direto pelo endereço do API Gateway, mas com throttling.
- **HTTP API + Lambda**: custo zero parado, US$ 1 por milhão de requisições e o nível gratuito permanente da Lambda cobre o uso esperado. Container ou servidor ligado teriam custo fixo (e IPv4 público é cobrado desde 2024, outra lição do Yamaha).
- **TypeScript na Lambda**: o mesmo idioma do app, então os tipos da resposta (zod) podem ser iguais nos dois lados, e o resto da equipe técnica do Felipe já usa.
- **DynamoDB on-demand com TTL**: sem servidor, custo por uso, TTL apaga sozinho o que venceu, e o `UpdateItem` com `ADD` e condição faz contador atômico para os limites sem trava. Um Redis gerenciado teria custo fixo mensal maior que o teto.
- **Terraform em vez de CDK**: a plataforma médica, na mesma conta, já usa Terraform; um jeito só de mexer na conta. O `plan` mostra a lista exata de recursos antes do primeiro `apply`, que é o passo de aprovação pedido na fase 3. O CDK exigiria bootstrap de CloudFormation na conta e esconde o plano atrás de um template sintetizado. Regra que vem do Yamaha: o Terraform só vale se for a fonte única; nada do que ele gerencia é mexido pelo console.
- **Estado remoto com lockfile do S3**: dispensa tabela de trava no DynamoDB (o `use_lockfile` existe desde o Terraform 1.10). O bucket do estado tem versionamento, para voltar um estado corrompido.
- **Budget + corte automático**: o Budgets avisa, mas não desliga Lambda. A Lambda de corte zera o throttling da rota padrão da API quando chega o aviso de 100%, então o custo para de crescer. Religar é rodar `terraform apply`, que devolve o throttling escrito no código (o corte cria um drift de propósito, e o próprio apply desfaz). O Budgets atualiza o gasto algumas vezes por dia; enquanto o aviso não chega, o throttling de 5 requisições por segundo segura o pior caso em poucos dólares por dia.
- **Sem segredo no repositório**: a fase 2 usa a OpenDota sem chave (nível gratuito). Não há credencial para guardar. Se um dia entrar chave, ela vai para o SSM Parameter Store como `SecureString`, lida pela Lambda, nunca no código nem no Terraform. As credenciais da AWS ficam só em `~/.aws/credentials` do PC do Felipe.
- **Scripts locais em vez de CI**: o deploy é de uma pessoa, poucas vezes por mês. Um pipeline com OIDC no GitHub é o próximo passo se mais alguém for publicar; agora seria estrutura sem uso.

## Limites conhecidos

- O endereço do API Gateway é público. O throttling e o limite por visitante seguram abuso; WAF custaria mais que o teto (US$ 5 por ACL mais regras).
- Um ataque ao CloudFront do site (não à API) não é cortado pela Lambda de corte. O alarme de 40% e o de previsão chegam por e-mail; a ação é manual (desligar a distribuição). Risco aceito pelo tamanho do projeto.
- Contas AWS novas podem ter limite de 10 execuções simultâneas de Lambda; por isso não há concorrência reservada (o throttling da API faz o papel).
- A etiqueta `projeto` precisa ser ativada como etiqueta de alocação de custo (aparece para ativar até 24 h depois do primeiro recurso etiquetado). Até lá, o budget do projeto mostra zero e vale o budget geral da conta (US$ 100) que já existe.
- O RTK do PC do Felipe filtra a saída do `aws` e do `terraform`: os comandos ficam em scripts `.sh` rodados com `bash`.

## Organização do repositório

- `api/` (TypeScript): `src/fonte/` (cliente da OpenDota), `src/cache/`, `src/limite/`, `src/contas/`, `src/partidas/`, `src/times/`, `src/patch/`, `src/http/` (handler e servidor local), `src/corte/` (Lambda de corte).
- `infra/bootstrap/` (Terraform, estado local): bucket do estado.
- `infra/` (Terraform, estado no S3): site, API, cache, custo.
- `scripts/`: `publicar.sh`, `voltar.sh`, `religar-busca.sh`.
