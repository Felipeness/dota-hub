# Decisão técnica: stack da fase 1

Data: 06/10/2026. Decidido pelo Felipe no brainstorming (opção 1 de 3).

## Escolha

- **App**: React + Vite + TypeScript, com o mapa em Three.js via react-three-fiber. Site estático (build de arquivos, sem servidor).
- **Exportação de dados**: Python 3.13 (a mesma linguagem dos projetos de análise), gerando JSON validado por JSON Schema.
- **Conteúdo escrito**: Markdown com frontmatter, versionado no repositório.
- **Execução na fase 1**: local (`npm run dev` e build estático). AWS fica para depois (S3 + CloudFront para o site; Lambda + DynamoDB na fase 2 da busca ao vivo).

## Por quê

- Mais leve para abrir no celular e mais barato de hospedar do que Next.js com servidor, que só valeria para SEO ou páginas geradas no servidor (não pedidos).
- Unity/Unreal exportado para web foi descartado: pesado no celular, lento para carregar e ruim para telas de texto, glossário e painéis.
- Python na exportação reaproveita o código e as convenções dos projetos `dota-imortal`, `dota-hane`, `dota-leonardo` e `dota-yuma` (por exemplo, `basemap.py` e as coordenadas normalizadas).
- Separar exportação (dados) de app (apresentação) e isolar a camada do mapa atende à decisão de começar em 2.5D e trocar o mapa depois sem refazer as telas.

## Organização do repositório

- `export/` (Python): lê os projetos de análise e gera `app/public/data/*.json`; schemas em `export/schemas/`.
- `content/` (Markdown): glossário e textos básico/avançado dos objetivos.
- `app/` (React + Vite + TS): módulos por domínio `map/`, `routes/`, `heroes/`, `players/`, `glossary/`, `search/`.
